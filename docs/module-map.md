# 逐光天气模块地图

本文定义逐光天气的最终模块边界。当前实现可以分阶段推进，但后续任务不得把产品缩窄成简单天气查询或 AI 文案工具。

## A. Location and Spot Module

目标：把用户输入的地点、平台返回的地点和本地摄影机位统一成可计算、可展示、可校验的地点对象。

功能范围：

- 地点搜索。
- Amap geocoding / reverse geocoding。
- 本地摄影机位数据库。
- GCJ-02 展示坐标。
- WGS84 计算坐标。
- 海拔和已验证机位元数据。
- 机位标签：云海、日出、日落、星空、银河、雪景、雾凇、交通、安全、开放状态等。
- 机位来源和验证状态：官方、社区、运营录入、待核验、已下线。

边界要求：

- 地图展示和高德返回坐标使用 GCJ-02。
- 天气、天文、地形、评分计算只使用 WGS84。
- 公共搜索优先返回本地地点和已验证摄影机位，再补充 Amap 结果。

## B. Weather Module

目标：把不同天气服务商的原始数据归一化为摄影评分可使用的天气事实。

功能范围：

- 实时天气。
- 小时级预报。
- 日级预报。
- 总云量。
- 低云 / 中云 / 高云。
- 湿度。
- 露点。
- 能见度。
- 风速 / 阵风 / 风向。
- 降水概率。
- 气压。
- 天气预警。
- 空气质量。
- 服务商字段缺失记录。
- 服务商更新时间、预报窗口和数据源标识。

边界要求：

- Weather Module 只提供确定性天气事实和归一化状态，不直接生成摄影结论。
- 缺少低中高云、能见度、露点等关键字段时必须记录缺失字段，并降低相关评分置信度。

## C. Astronomy Module

目标：用本地确定性天文计算提供摄影时间窗口和月光/银河约束。

功能范围：

- 日出 / 日落。
- 民用、航海、天文晨昏光。
- 月相。
- 月亮照明比例。
- 月出 / 月落。
- 月亮高度。
- 无月夜（moonless night）。
- 银河窗口（Milky Way window）。
- 银心高度 / 方向（Galactic Center altitude/direction）。
- 可行时预留主要天象事件 hooks。
- 月光对星空、银河和夜景曝光的影响提示。

边界要求：

- 默认不依赖在线天文 API。
- 天文事实不得由 DeepSeek 或其他 AI 生成。
- 只使用 WGS84 坐标和明确时区。

## D. Terrain Module

目标：提供山地摄影所需的海拔、遮挡和地形潜力判断。

功能范围：

- 机位海拔。
- 周边谷地海拔。
- 高差。
- 地平线遮挡。
- 日出 / 日落遮挡。
- 银河方向遮挡。
- 云海地形潜力。
- 山地风险辅助字段：陡峭、低温、积雪、道路可达性等可扩展元数据。

边界要求：

- 初期可以使用 mock/local 数据，但正式判断需要可追溯 DEM 或人工核验机位数据。
- 地形结果影响云海、白墙、日出日落、银河和综合出行价值，但不能替代天气事实。

## E. Light Pollution Module

目标：给星空和银河拍摄提供光污染约束。

功能范围：

- 卫星夜光参考等级。
- 不输出现场实测 SQM 或测量 Bortle 等级。
- 尽量使用 NASA VIIRS-compatible / 公共光污染 GeoTIFF 数据集。
- 离线数据、瓦片或区域缓存策略。
- 城市方向光害提示。
- 与月光、云量、透明度共同影响星空/银河评分。

边界要求：

- 默认不按每次请求调用昂贵在线 API。
- 光污染数据必须标注数据年份、分辨率和缓存状态。

## F. Photography Scoring Module

目标：把天气、天文、地形、光污染和机位信息转化为可解释摄影决策。

功能范围：

- 云海评分。
- 白墙风险评分。
- 日出霞光评分。
- 日落霞光评分。
- 星空评分。
- 银河评分。
- 透明度评分。
- 综合出行价值。
- 置信度、缺失字段、冲突数据和关键依据。
- 备选题材和备选时间窗口。

边界要求：

- 评分只使用归一化后的确定性输入。
- 评分结果必须可解释，不直接读取服务商原始 JSON。
- AI Explanation Module 可以解释评分，但不得覆盖评分。

## G. AI Explanation Module

目标：把确定性评分、风险和建议组织成专业、清晰、可读的摄影建议。

功能范围：

- DeepSeek explanation only。
- 解释 deterministic scores。
- 总结风险。
- 提供摄影建议。
- 提供备选拍摄计划。
- 按用户题材目标调整表达重点。

边界要求：

- 不计算天气事实。
- 不计算天文事实。
- 不计算地形事实。
- 不生成或覆盖坐标。
- 不编造缺失数据。
- 没有真实 AI 配置或用户未触发时，使用规则解释或不生成 AI 解释。

## H. User Center Module

目标：让摄影师保存、复盘和管理自己的拍摄判断。

功能范围：

- 查询历史。
- 收藏机位。
- 已保存报告。
- 额度。
- 后续付费计划。
- 历史报告对比。
- 用户反馈：实际是否出片、云海是否成立、银河是否可见、白墙是否发生。

边界要求：

- 早期可以先显示占位和空状态。
- 付费、额度和报告归档应在成本控制和数据源透明度基础上实现。
