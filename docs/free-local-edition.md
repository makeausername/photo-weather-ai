# 免费版本地开发

本次为本地开发版本，没有发布或修改服务器。公开入口无需账号，所有题材和 24 / 48 / 72 / 168 小时范围均开放。

## 启动

本机已初始化独立数据库。在仓库根目录运行：

```powershell
npm run dev:free
```

也可以使用 `pnpm dev:free`。首页为 `http://127.0.0.1:3100`，真实后台为 `/admin`，API 为 `http://127.0.0.1:4101`。只监听本机。脚本先构建 geo 包、启动独立本地 PostgreSQL，前端使用独立 `.next-free` 缓存。首次初始化步骤见文末“独立本地数据库与真实后台”。控制台按 Ctrl+C 停止应用，再运行 `npm run stop:free-db` 可停止数据库并保留数据。

脚本读取现有 `.env.local`，不写入它；数据库地址和登录签名密钥由独立本地配置覆盖，管理员绕过和只读预览均关闭。管理员账号见 `.runtime/free-local/admin-login.json`。Open-Meteo 使用免费端点；和风天气的 Host 与 API Key 可在真实后台保存。密钥不进入前端。没有和风配置时仍可查询 Open-Meteo 真实数据；不使用模拟天气填充页面。

本地天文默认使用已有 JS 算法，银河详情明确标注简化估算。如果已运行项目自有天文服务，可设置 `FREE_LOCAL_ASTRO=true` 和对应服务地址；这是本地计算，不是第三方气象源。

## 国外源站与 Cloudflare 的后续部署方案

建议链路：浏览器 → Cloudflare → 国外服务器上的 Caddy → Next.js / API。由 API 服务器请求和风与 Open-Meteo，浏览器仅调用同域 `/api/service`；CDN 不代替源站访问气象供应商。现有 Caddy 模板已补充 `/api/service/*` 路由，并放在旧 `/api/*` 路由之前，避免把 `/service/forecast/calculate` 错转给 API。只修改了仓库模板，未应用到任何服务器。

- Cloudflare 使用 **Full (strict)**，源站配置有效且匹配域名的证书。不要使用 Flexible。[官方说明](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/)
- 优先缓存 `/_next/static/*` 等带版本号的静态文件；API、后台、认证路径明确绕过缓存。初期不要添加全站 Cache Everything，避免缓存错误响应或混淆 Next.js HTML 与 RSC 响应。Cloudflare 默认不缓存 HTML / JSON，免费版预报的 POST 请求仍由应用缓存处理。[缓存默认行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
- API 和数据库端口不直接暴露公网。源站反向代理应仅信任实际 Cloudflare 上游，并正确传递真实访客 IP；上线前验证匿名限流不会把所有访客算成同一人，也不能被伪造转发头绕过。当前仍沿用原项目的代理信任设置，此项需要针对实际部署网络验证。
- Cloudflare 普通套餐不包含中国大陆节点；China Network 是 Enterprise 的独立订阅。大陆访问速度需要在选定机房后实测移动、联通、电信，不能仅凭“套 Cloudflare”保证加速。[官方说明](https://developers.cloudflare.com/china-network/)
- Open-Meteo 免费接口面向非商业使用，并有分钟、小时、日、月调用限额。上线前检查缓存、限流与流量预算，保持数据署名；免费开放网站不等于上游调用无限量。[官方额度](https://open-meteo.com/en/pricing)

本次未购买服务器、修改域名 / Cloudflare 设置或执行部署。正式部署前仍需 Linux 构建、代理链路、真实供应商及真实手机验收。

## 真实地图与高德接口（2026-10-23，后续增量）

云海页已改为真实地理底图：桌面沿用左侧机位、中间地图、右侧拍摄预报；手机直接拖动与双指缩放，没有“操作地图”开关和底图切换栏。手机可切换地点列表与拍摄预报。点选地图先确认坐标，再查询天气，避免拖动触发天气请求；相近标记按屏幕距离聚合。地图独立于天气请求，加载中或预报失败仍可浏览。

正式运行只使用高德。无凭据的本地 `dev:free` 才启用 OpenStreetMap / Leaflet 预览；生产环境即使误设 `LOCAL_MAP_PREVIEW=true` 也不会启用 OSM。OSM 只作地理底图，不引入新天气源，按需加载当前视窗、保留署名和浏览器缓存，不提供离线下载。参考 [OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。

高德接入沿用 `/admin/providers/geo` 的 `geo:amap` 记录与现有密钥保护机制，在原设置表单补充 `secretJson.jsApiKey`、`secretJson.securityJsCode`。服务商开关和“启用真实调用”都需开启。原 `apiKey` 是 Web 服务 Key，不能拿来冒充 JS API Key；原字段及历史配置保留。数据库不可用时，可在 API 服务环境设置 `ENABLE_REAL_AMAP=true`、`AMAP_JS_API_KEY` 和 `AMAP_SECURITY_JS_CODE`，重启服务生效。

公共配置接口：`GET /api/service/maps/config`，只返回 SDK 必需的公开 JS Key，不返回安全密钥或旧 Web 服务 Key。高德安全代理：`GET /api/service/maps/_AMapService/*`，限定地图样式、POI 与逆地理编码路径，由服务端加签，接入现有公共接口限流；高德天气路径禁止通过代理。地图展示使用 GCJ-02，点击选点转回 WGS84 后进入原天气流程。现有地点文字搜索仍由 Open-Meteo 提供，本轮未改动该搜索服务。

高德控制台需配置正式域名白名单，JS Key 和 securityJsCode 必须配对。前台免注册不代表后台免登录。当前没有旧服务器凭据，已完成接口和隔离测试，真实高德地图、域名白名单和账户额度仍需用户上线前联调。[高德官方安全代理说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

Cloudflare 沿用现有同源 `/api/service/*` 路由，不对地图配置、安全代理应用 Cache Everything；高德 SDK 与底图由浏览器请求高德域名。CDN 不能消除用户网络到高德的可用性差异。没有改动实际服务器、Cloudflare 或域名。

npm install --prefix .runtime/free-local/postgres-runtime @embedded-postgres/windows-x64@17.10.0-beta.17 --ignore-scripts --no-audit --no-fund
npm run setup:free-local
npm run dev:free
