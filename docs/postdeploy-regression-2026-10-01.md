# 多机位实测问题修复与回归记录

## 修复范围

本次针对 2026-09-30 部署后实测发现的七类问题修复：

| 问题 | 修复结果 |
| --- | --- |
| 跨来源气温差异未传递到温度与穿衣提示 | 复用已有同有效小时分歧检测，记录最大分歧对应时间；中、高分歧分别限制天气置信度上限，并向温度卡和装备建议传递复核及备用保暖层提示。温度、湿度与露点仍保留同源关系。 |
| 实况雨量被称为预计降水 | 穿衣建议识别观测数据，显示“观测小时降水”，未来雨量仍按预报标注。 |
| 详情日期、阶段和窗口与来源链接不符 | 云海、霞光按链接日期选择已有逐日评估；朝霞与晚霞分别定位，检查原窗口起止时间。原窗口或逐日数据已消失时明确提示返回重选。无高分朝霞窗口时选择预报范围内下一次日出日期。 |
| 星空云量说明混用平均值和峰值 | 局部峰值触发风险时同时显示平均和最高云量，避免将局部遮挡表述为整窗不可见。 |
| 霞光方向地形已有数值却称尚未返回 | 根据当前方向评估的数据可用性和置信度显示状态。 |
| 英文限流错误及立即自动重试 | 服务端和客户端显示中文等待秒数，暴露 Retry-After；429 不进入立即自动重试。 |
| 星空入口与小时摘要混用观测夜 | 六张入口卡使用同一最佳观测夜；小时摘要说明绑定实际入选小时所属窗口。 |

补充优化：云海、霞光预览窗口显示日期；未知海拔的地点提示当前坐标不一定是山顶机位；7 天加载状态说明正在汇总多日数据；星空覆盖标签说明仅指所选观测窗口，不代表整夜；前端缓存版本升级，避免复用旧展示结果。

温度分歧表示模型及来源存在不确定性，不能证明任一来源是真实地面温度。已知或未知源海拔的差异仍需复核，未直接平均不同高度的温湿露点数据，也未根据辅助模型覆盖真实观测。

## 服务器更新

在原服务器执行：

```bash
cd /opt/photo-weather-ai
DEPLOY_BRANCH=main bash scripts/update.sh
docker compose --env-file .env.production -f docker-compose.prod.yml ps
git rev-parse --short HEAD
```

更新脚本会拉取 main、构建生产镜像并重启服务。若某服务异常，查看相应日志：

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml logs --tail=100 api web astro-service
```

更新后浏览器强制刷新页面，重新查询多个机位，并检查温度分歧提示、云海/朝晚霞详情日期和星空预览的观测夜。
